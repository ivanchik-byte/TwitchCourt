# Архитектура системы Stream Tribunal

Техническое описание внутреннего устройства сервера, модулей, игрового движка, машины состояний суда, звукового тракта и сетевых протоколов.

---

## 1. Общий обзор системы

Stream Tribunal спроектирован как компактный монолитный сервис на языке Go. Приложение компилируется в один автономный исполняемый файл без внешних runtime-зависимостей. Все клиентские ресурсы (веб-интерфейс пульта управления на React 19 и браузерный оверлей для OBS на HTML5 Canvas) встраиваются в бинарник на этапе сборки через стандартный механизм `go:embed`.

```
                    Twitch Чат / Донаты / Сигналы стримера
                                      │
                                      ▼
                      Сетевые адаптеры (Bot / Ingest)
             Twitch IRC | Helix API | Centrifugo | EventSub | REST
                                      │
                                      ▼
                        Игровой движок (Court Engine)
          Очередь подсудимых | Тайминги | Память | Машина состояний
                                      │
                   ┌──────────────────┴──────────────────┐
                   ▼                                     ▼
        Мозг судьи (AI Engine)              Звуковой тракт (Audio Pipeline)
    LLM потоковый разбор SSE            Edge TTS | Silero sidecar | Piper
    Анализ улик и генерация реплик      Синхронизация фонем и анимаций
                   │                                     │
                   └──────────────────┬──────────────────┘
                                      │
                                      ▼
                         Шина событий (WebSocket Hub)
                   Маршрутизация событий оверлея и пульта
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
          OBS Browser Source                  Пульт управления (Cockpit)
       Визуальный оверлей 1920x1080       React 19 дашборд стримера :7890
```

## 3. Машина состояний суда (Court State Machine)

Жизненный цикл судебного заседания строго линеен и контролируется движком `internal/court/engine.go`:

```
┌──────┐      старт дела      ┌────────────┐     таймер 25с      ┌───────────┐
│ IDLE │ ───────────────────> │ INDICTMENT │ ──────────────────> │ TESTIMONY │
└──────┘                      └────────────┘                     └───────────┘
   ▲                                                                   │
   │                                                                   │ таймер 20с
   │                                                                   ▼
┌─────────┐   пауза 6с        ┌──────────────┐   протест судьи   ┌───────────┐
│ VERDICT │ <──────────────── │ DELIBERATION │ <──────────────── │  DEFENSE  │
└─────────┘                   └──────────────┘                   └───────────┘
```

1. **Фаза IDLE (Ожидание):** Суд свободен. Работает очередь чата `!court`, принимаются донаты, доступны кнопки запуска дел в пульте.
2. **Фаза INDICTMENT (Обвинение):** Выбран подсудимый. Движок запрашивает у LLM вступительную речь судьи. Модель называет статью, номер дела и формулирует провокационный вопрос подсудимому.
3. **Фаза TESTIMONY (Показания):** Включается таймер (по умолчанию 25 секунд). Бот слушает сообщения подсудимого в чате Twitch и транслирует их через WebSocket в плашку оверлея. Попутно донаты зрителей приобщаются как показания свидетелей.
4. **Фаза DEFENSE (Защита):** Включается микрофон стримера в пульте управления (таймер 20 секунд). Браузер распознает речь через Web Speech API и отправляет тезисы защиты на сервер. Если стример молчит, подставляется заготовка `silent_defense`.
5. **Фаза OBJECTION (Протест):** Нейросеть генерирует колкий ответ на аргументы стримера. Воспроизводится звук возражения, анимация судьи и удар молотком.
6. **Фаза DELIBERATION (Совещание):** Судья анализирует все собранные материалы (обвинение, ответы подсудимого, аргументы стримера, доносы чата и взятки) и выносит мотивированное решение.
7. **Фаза VERDICT (Приговор):** Финализация дела. Судья оглашает ВИНОВЕН или НЕВИНОВЕН, бьет молотком трижды, озвучивает меру наказания или твист взятки. Приговор отправляется в чат. В пульте стримера загорается блок ручного исполнения приговора. Через 6 секунд система возвращается в IDLE.

## 4. Потоковый конвейер речи и анимаций (Streaming Audio Pipeline)

Ключевая проблема разговорных игровых систем: зритель не готов ждать 3-5 секунд, пока нейросеть допишет длинный ответ.

Я реализовал потоковый разбор на уровне предложений (`internal/ai/chunker.go`):
1. LLM отдает токены через Server-Sent Events (SSE).
2. Чанкер накапливает токены до первого знака препинания (. ! ?).
3. Первое готовое предложение немедленно отправляется в движок синтеза речи (Edge TTS или Silero).
4. Пока звучит первая фраза (около 1.5 секунд), нейросеть успевает догенерировать остальной текст.
5. Время от окончания фазы до первого звука речи судьи в эфире сокращено до 400-700 миллисекунд.

## 5. Долговременная память и учет рецидивов

Файл `data/memory.json` хранит историю всех проведенных процессов. Для каждого дела сохраняются:
* Никнейм подсудимого и формулировка статьи.
* Итоговый вердикт (виновен / невиновен) и голоса присяжных.
* Число свидетелей и краткая выжимка стенограммы.

Если один и тот же зритель оказывается на скамье в третий раз, движок автоматически добавляет в промпт судьи пометку: зритель является рецидивистом, зал помнит прошлые проступки. Судья начинает припоминать старые грехи в новых приговорах.
